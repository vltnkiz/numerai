Matrix Multiplication and the Inverse

Lesson 5's code leaned on two ideas without spelling them out: Xβ (matrix multiplication) and pinv(X) (a generalized inverse). This lesson fills that gap with the specific numbers you already computed, so it isn't abstract.

Primary sources: 3Blue1Brown, "Matrix multiplication as composition" and "Inverse matrices, column space and null space" — both from the Essence of Linear Algebra series. Geometric, visual, no prior linear algebra assumed. Worth watching in full; this lesson gives you just enough to read the neutralization code with understanding.

Matrix multiplication is just a batch of dot products

A matrix times a vector produces a new vector. Each entry of the output is the dot product of one row of the matrix with the input vector — multiply matching entries, add them up. That's the entire rule.

The inverse: the matrix that "undoes" a matrix

For a square matrix A, its inverse A⁻¹ is defined by one property: A · A⁻¹ = I. Multiplying by A then by A⁻¹ gets you back to where you started — exactly like multiplying by 5 then by 1/5.

A = [[2, 0], [0, 4]] A⁻¹ = [[0.5, 0], [0, 0.25]] A · A⁻¹ = [[2×0.5 + 0×0, 2×0 + 0×0.25], [0×0.5 + 4×0, 0×0 + 4×0.25]] = [[1, 0], [0, 1]] = I

Two things worth knowing without proving: the inverse only exists for square matrices (same number of rows and columns), and even among square matrices, some don't have one — if the matrix "flattens" space into a lower dimension (e.g. every row is a multiple of another), there's no way to undo that collapse. 3Blue1Brown's video covers this geometrically far better than a paragraph of text can.

Why the code uses lstsq, not a literal inverse

Lesson 5's X (the neutralizer_arr) has one row per stock and one column per feature (plus the intercept column) — thousands of rows, a few hundred columns. That's not square, so X⁻¹ doesn't exist at all. The pseudo-inverse, pinv(X), is what generalizes "inverse" to non-square matrices: it's the matrix that gets you the closest possible least-squares answer even when a perfect undo is impossible. np.linalg.lstsq computes the effect of pinv(X) · prediction without ever forming pinv(X) explicitly, which is faster and more numerically stable.

Numerai's feature matrix X has ~5,000 stock-rows and ~700 feature-columns in a given era. Why can't the code just compute a literal inverse of X and multiply it by the predictions?

With this, the pseudo-inverse in Lesson 5 stops being a black box: it's the tool that does the same job as a regular inverse (solve Xβ = prediction for β) but works for the wide, non-square, real-world case — and it's the same closest-fit idea as the least-squares regression from Lesson 3, just written in matrix form.

If the leap from "2×2 numbers on a page" to "a 5,000×700 feature matrix" feels too big, ask your teaching agent to walk through a 3-row, 2-column example end to end — small enough to trace by hand, big enough to be genuinely non-square.
